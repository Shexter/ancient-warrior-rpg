# Terminal engine (`src/engine/`, `src/platform/terminal_*.cpp`)

- **Framebuffer:** a grid of `Cell{glyph, fg, bg}`. Drawing calls clip silently; `at()` requires in-bounds coordinates. `text()` is ASCII only (other bytes show as `?`).
- **Renderer:** `present(frame, out)` appends escape bytes for only the cells that changed since the last frame, wrapped in synchronized-update markers (`ESC[?2026h`/`l`). A first frame, a size change or `invalidate()` clears the screen and redraws everything. An identical frame appends nothing. Colors are truecolor, or the 256-color cube in `Ansi256` mode. Colors and cursor position are re-learned on every present, and the cursor is treated as unknown after the last column.
- **Color mode:** `platform::detectColorMode()` is truecolor if `COLORTERM` is `truecolor`/`24bit` or `WT_SESSION` is set, otherwise 256-color.
- **Input:** `InputDecoder` turns raw POSIX bytes into keys: arrows (`ESC [ A-D` and `ESC O A-D`), Enter (`\r`, `\n`), Backspace (127, 8), Tab, printable characters, a lone ESC, and SGR mouse reports (`ESC [ < b ; x ; y M`): a left press or touch, with any modifier, becomes `Key::Click` at the 0-based cell; releases, other buttons, drags, wheel events and malformed reports are dropped, and a legacy `ESC [ M` report's three raw bytes are skipped. Other escape sequences and control bytes are dropped. Each `feed()` is parsed on its own, so a sequence split across two reads is not reassembled. Windows reads key events natively and does not turn on mouse reporting.
- **Key actions:** every `KeyEvent` has an `action`: `Press` (the default), `Repeat` or `Release`. The decoder also reads kitty keyboard protocol reports:
  - `CSI code[:…] [; mods[:event]] u` gives Enter (13), Esc (27), Backspace (127), Tab (9) and printable characters. Letters are uppercased under Shift or Caps Lock, but not both.
  - Keys held with Alt, Ctrl or Super, modifier keys on their own, other functional keys and unknown event types are dropped.
  - A Ctrl+C press sets `takeInterrupt()`, and the POSIX terminal answers it with `raise(SIGINT)`, because the terminal sends no `0x03` while the protocol is on.
  - Arrows read their action from `CSI 1 ; mods:event A-D`. With no event field (`ESC [ A`, or Ctrl+Right's `ESC [ 1 ; 5 C`) they are a press.
  - Windows reports key-up as `Release`, and a down event for a key already down as `Repeat`.
- **Key action mode:**
  - `Screen::wantsKeyActions()` (false by default) opts a screen in. `App` drops `Release` and turns `Repeat` into `Press` for every other screen, so they see exactly the keys of a plain terminal.
  - Before each update, `App` calls `LoopIo::setKeyActions(on)` when the top screen's wish changes (the default `LoopIo` ignores it).
  - The POSIX terminal sends `kKittyQuery` (`CSI ? u` then `CSI c`) at startup and waits up to 200 ms. `probeKittyReply` treats a `CSI ? flags u` before the `CSI ? … c` reply as support. Bytes read while waiting are fed to the decoder, which drops the replies.
  - Only on a terminal that supports it, `setKeyActions` pushes flags 1|2|8 (`CSI > 11 u`) or pops them (`CSI < u`). A pushed protocol is popped in the same signal-safe restore path, via `leaveSequence(pushed)`, and only then.
- **HeldKeys** (`app/held_keys.*`) turns the arrows and W/A/S/D (any case) into a movement direction. Until a `Release` has been seen it only reports a direction pressed or repeated in this tick, which is the fallback for plain terminals. After that, a direction is held from press to release and the most recently pressed one wins. A press and release in the same tick still counts once.
- **Loop:** fixed 1/60 s steps with at most 5 steps per frame (extra time is dropped). Keys go to the first step after they arrive, once, and wait if a frame runs no step. The terminal size is checked every frame: below 80x24 only the centered resize prompt is drawn, `update` is skipped and keys typed meanwhile are dropped. After the frame's updates the loop asks an optional callback which canvas size it wants for the current terminal (80x24 without one). A size below 80x24 or bigger than the terminal falls back to 80x24. The canvas is reallocated only when that size changes, drawn, then centered, with the margin filled with the loop's background color. So a screen can switch canvas size on a live resize.
- **Terminal (POSIX):** raw mode with `ISIG` kept, alternate screen, hidden cursor, and mouse reporting in SGR form (`?1000h`, `?1006h`), so phone terminals such as Termux deliver taps as clicks. `kEnterSequence` and `kLeaveSequence` (`terminal.hpp`) hold the bytes; leaving turns off every mode entered. It restores on normal exit, on `SIGINT`/`SIGTERM`/`SIGHUP`/`SIGABRT` (then re-raises the signal; `SIGABRT` covers failed asserts) and via `atexit`. Restoring is idempotent and signal-safe. Not handled: `SIGTSTP` (Ctrl+Z) leaves the terminal raw while suspended. The constructor throws if stdin or stdout is not a terminal.
- **Terminal (Windows):** same contract using console modes, UTF-8 output code page and a console control handler. Written and compile-checked, but not yet run on Windows.
- The chunk 8-9 demo (and `--demo-stats`) was replaced by the real app in task 10.1; see app.md.

- **Canvas and minimum size:** each frame the loop asks for a canvas before and after the updates. It accepts the phone canvas `kPortraitCanvas` (48×44) or anything 80×24 and up; anything else, or a canvas larger than the terminal, falls back to 80×24. If that doesn't fit either, it shows the resize prompt ("…at least 80×24, or 48×44 on a phone (now W×H)"), word-wrapped to the terminal's width and centered, and drops keys typed meanwhile.
- **Clicks in the loop:** a click's terminal cell is turned into a canvas cell using where the canvas was last drawn (it is centered in larger terminals); clicks on the margin are dropped.
