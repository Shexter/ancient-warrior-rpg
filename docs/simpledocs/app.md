# App: screens and widgets

**Command line:** `heroes [--seed N] [--data-dir PATH]`. Unknown options or bad values print the error and usage to stderr and exit 2. The data directory is `--data-dir`, else `HEROES_DATA_DIR`, else the source tree's `data/`. Content errors are printed one per line and the game exits 2 **before** the terminal is switched to raw mode or the alternate screen (a CTest case checks this). Sprites are loaded next (`<data-dir>/../assets/sprites`: `hero_<path>.sprite` for every path, every enemy's sprite, `monster.sprite`); a missing or invalid one is printed and the game exits 2, also before the terminal changes. If no save location can be found (no `HOME`/`APPDATA` and no `HEROES_SAVE_DIR`) it exits 2. Other startup failures (for example not running in a terminal) print `heroes: error: ...` and exit 1 after the terminal is restored.

**Session:** content, the loaded sprites, the save path, the `--seed` for new games, the current `GameState` (none until a game is started or loaded), `dirty` (changed since the last successful save), `saveOwned` (this session loaded or wrote the save file) and the Hub's last message.

**App:** a stack of `Screen`s on the fixed-step loop. Each step the top screen gets the new keys and returns `Stay`, `Push`, `Pop`, `Replace` (pop then push) or `Quit`. Quit, or popping the last screen, ends the program with exit code 0. Only the top screen is drawn; dialogs are drawn by the screen that owns them. The canvas is 80x24, centered in larger terminals with the `bg` color around it.

**Widgets** (`src/app/widgets.hpp`, colors from ui.md's palette):
- `Menu`: vertical (↑/↓, `w`/`s`) or horizontal (←/→, `a`/`d`). Selection wraps and skips disabled items; Enter or `1`-`9` chooses an enabled item. The selected row shows `▶` in the accent color, disabled rows are dim, and an optional dim note follows the label. An unfocused menu (the other list of a two-list screen) hides its `▶`.
- `TextInput` (printable ASCII up to a max length, blinking `_`), `NumberInput` (digits only, no more digits than the maximum has; Enter on an empty or out-of-range value shows "Enter a number from MIN to MAX" in the damage color).
- `MessageBox` (centered, at most 60 columns, word-wrapped, Enter or Esc dismisses), `ConfirmBox` (`Y`/`N`, Esc means No).
- `Typewriter`: 40 characters per second; the first Enter reveals the rest, the second finishes.
- Status panel: **rows 0-4** (ui.md says 0-3; see below). Row 1: name, path, level, HP bar (20 cells, colored by the >50% / >20% thresholds), MP bar (8 cells). Row 2: ATK/DEF/LIFE including equipment, EXP, Next, Gold. Row 3: `Weapon <name>[+N]   Armor <name>`, with `+N` only above upgrade 1 and `—` for an empty slot. Text is clipped at the border, never drawn over it.

**Screens so far:**
- **Title:** banner, New Game / Continue / Quit. Continue is disabled when no save file exists. Continue loads the save; on any load error a MessageBox explains it (damaged, newer version, unreadable), the file is left untouched and the Title stays, so New Game is still available. A successful load marks the save as owned and goes to the Hub with "Welcome back, NAME."
- **Intro:** the opening story on a typewriter (Enter reveals, Enter again continues). Esc returns to the Title.
- **Create Hero:** name (TextInput, max 8; invalid names show `describe(InvalidName)` and ask again), then the path-intro story, then the WARRIOR PATHS menu with a preview box (cols 30-78: name, flavor, base stats, EXP multiplier, the path's sprite). Enter creates the game with `--seed` or, without it, one `std::random_device` value, marks it unsaved and goes to the Hub. Esc on the name returns to the Title; Esc later returns to the name.
- **Hub:** status panel, hero sprite at (4, 6), menu at (34, 7): Training, Mission, Town, Save, Quit. Training and Mission are disabled with a dim reason when the hero can't adventure ("Fallen: visit the Guildmaster" at 0 HP, else "Equip a weapon and armor"); Mission is also disabled below the lowest mission level ("Requires Lv 20"). The menu refreshes every step, keeping the selection. Row 22 shows the last message.
  - **Save:** if a save file exists that this session neither loaded nor wrote, it first asks "Replace the existing save?" (No keeps the file). A successful save clears `dirty`, marks the file owned and shows "Game saved."; a failure shows why and leaves the old save as it was.
  - **Quit / Esc:** quits at once if nothing is unsaved, otherwise asks "Quit without saving?".
  - Training opens Training Setup, Town opens the Town menu. Mission does nothing yet (task 10.5).
- **Training Setup:** status panel, then "Cave level (1–30)" and "Rounds (1–100)" NumberInputs. On the second Enter the whole session runs at once through `runTraining` (gold, EXP, drops and HP are applied immediately and the game is marked unsaved), then playback replaces the screen. A refused session shows `describe()` and returns to the Hub. Esc returns to the Hub without training.
- **Training Playback:** hero sprite left, `monster.sprite` at (56, 6) with its name and HP bar below, the hero's HP bar at the bottom. The round's events replay at 10 per second (HP bars follow each `Damaged`/`Healed`), then the round summary ("Round 3/10 · Bat defeated · +1000 gold · +1000 exp · Drop: Topaz", or "· Bag full, Topaz lost", "Defeated by the Bat", "Stalemate with the Bat") stays up for 1 s before the next round. Enter finishes the current round (or ends the pause); Esc jumps to the totals.
- **Training totals:** status panel (already showing the new values), rounds won of rounds fought, gold and EXP as the net change since before the session (EXP can be negative after a defeat), levels gained, drops (and drops lost to a full bag), and "ARIA has been injured badly" in the damage color after a defeat. Enter returns to the Hub with "Training: won W of N rounds.".
- **Town screens** (`src/app/screens/town.hpp`): the Town menu (Merchant, Blacksmith, Guildmaster, Bank, Back) and each NPC screen show the status panel, a title on row 5, their content on rows 6-21 and a dim hint on row 22. Esc goes back one screen. Every action goes through the `game::` town function; a refusal shows its `describe()` text and changes nothing, a success marks the game unsaved. Dialogs (message, yes/no, number or name prompt, a choice list with Esc to back out) open one at a time over the screen, and the next step of a flow opens when the previous dialog closes.
  - **Merchant:** a fallen hero only sees "I have no business with you!" and is sent back. Otherwise "For sale" (items with a price, price in gold color) on the left and "Your bag" (10 slots, "(empty)" dim) on the right; Tab switches lists, and the highlighted item's description shows on row 19. Enter on a for-sale item asks "How many? (1–99)" with a live total, then buys. Enter on a bag item offers Sell (asks how many, up to what you hold), Auction and Cancel, with the ones that don't apply disabled and a note saying why. An auction is settled immediately (the item and gold change at once); if it sold, the accepted bids appear one every 600 ms ("Bid accepted at 550…", opening bid first) and then "Merchant fee is 10%. You receive N gold."; Enter skips the show. If nobody came: "No buyer came. The Topaz stays in your bag."
  - **Blacksmith:** a fallen hero sees "Empty soul, you don't belong here" and is sent back. Change Equipment: pick a slot, then a weapon or armor from the bag; swapping out gear above Lv 1 first asks "Your upgraded weapon will return to Lv 1. Continue?". Upgrade: pick an equipped slot, then the screen shows "Iron Sword  Lv 1 → Lv 2" and the material, EXP and gold costs, each line green if you have enough and red if not; Enter asks to confirm (at Lv 10 it says the item is maxed). Forge: the recipes, with the highlighted one's ingredients as have/need counts (green or red) and the success chance; Enter confirms, then "Forging SUCCESS!!! You now possess X" or "Forging FAILED, the materials are lost...".
  - **Guildmaster:** a hero at 0 HP is revived on entry with "Great warrior, be careful next time... (revived for N gold)". Restoration lists the bag's consumables and uses one. Build Charisma (disabled below Lv 10 with "Requires Lv 10") picks a stat, asks "EXP to sacrifice" with a live "→ +G Max HP for P gold" preview, then confirms. Learn Skill lists the skills with their level, gold and key item, each green when met and red when not ("Learned" once known); Enter learns. Change Name shows "The fee is 50000 gold." and asks for the new name.
  - **Bank:** without an account it asks "Open an account for 10000 gold?" (No, or a refusal, goes back). With one: "Bank" | "Your bag", Tab switches, Enter asks how many and moves them (works for a fallen hero too).

**Spec drift:** ui.md puts the Create Hero sprite at col 60, where a 24-wide sprite would run past column 79, so it is drawn at col 52 inside the preview box. ui.md's status panel puts gear on row 2 in rows 0-3, but with real item names that line needs about 84 columns, so gear moved to its own line and the panel uses rows 0-4. Row 4 was unused on every screen that shows the panel. `App` takes the terminal (as `LoopIo`), the renderer and the first screen instead of the `Session` from interfaces.md §14, since it never uses the session itself. The Blacksmith's Upgrade view writes levels as "Lv 1 → Lv 2" rather than the status panel's "+N" so level 1 has a name.
