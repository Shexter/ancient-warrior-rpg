# App: screens and widgets

**Startup:** mods load with the content, and their log lines print to stderr first (see `mods.md`).

**Command line:** `heroes [--seed N] [--data-dir PATH] [--layout auto|compact|portrait] [--art glyph|blocks]`. `--layout` (default `auto`) and `--art` (default `glyph`) are copied into the `Session`. They pick the large layouts and their look (see **Large layouts** below). Unknown options or bad values print the error and usage to stderr and exit 2. The data directory is `--data-dir`, else `HEROES_DATA_DIR`, else the source tree's `data/`. Content errors are printed one per line and the game exits 2 **before** the terminal is switched to raw mode or the alternate screen (a CTest case checks this). The Overworld world files are loaded next and fail the same way (see `overworld.md`; the `heroes_reports_bad_world` CTest case checks it). Sprites are loaded after that (`<data-dir>/../assets/sprites`: `hero_<path>.sprite` for every path, every enemy's sprite, `monster.sprite`); a missing or invalid one is printed and the game exits 2, also before the terminal changes. If no save location can be found (no `HOME`/`APPDATA` and no `HEROES_SAVE_DIR`) it exits 2. Other startup failures (for example not running in a terminal) print `heroes: error: ...` and exit 1 after the terminal is restored.

**Session:** content, the loaded sprites, the save path, the `--seed` for new games, the current `GameState` (none until a game is started or loaded), `dirty` (changed since the last successful save), `saveOwned` (this session loaded or wrote the save file), the Hub's last message, and the loaded world (`world`, set at startup, read by the Hub's Explore and the Overworld).

**App:** a stack of `Screen`s on the fixed-step loop. Each step the top screen gets the new keys and returns `Stay`, `Push`, `Pop`, `Replace` (pop then push) or `Quit`. Quit, or popping the last screen, ends the program with exit code 0. Only the top screen is drawn; dialogs are drawn by the screen that owns them. Each frame the top screen's `canvasSize(terminal)` picks the canvas (80x24 unless the screen overrides it), centered in larger terminals with the `bg` color around it.

**Widgets** (`src/app/widgets.hpp`, colors from ui.md's palette):
- `Menu`: vertical (↑/↓, `w`/`s`) or horizontal (←/→, `a`/`d`). Selection wraps and skips disabled items; Enter or `1`-`9` chooses an enabled item (a horizontal menu also moves with ↑↓), and so does a tap on a row where it was last drawn (a vertical row anywhere along its width, a horizontal item on its label). The selected row shows `▶` in the accent color, disabled rows are dim, and an optional dim note follows the label. An unfocused menu (the other list of a two-list screen) hides its `▶`.
- `TextInput` (printable ASCII up to a max length, blinking `_`), `NumberInput` (digits only, no more digits than the maximum has; Enter on an empty or out-of-range value shows "Enter a number from MIN to MAX" in the damage color).
- `MessageBox` (centered, at most 60 columns, word-wrapped, Enter, Esc or a tap anywhere dismisses), `ConfirmBox` (`Y`/`N` or a tap on `[Y]es`/`[N]o`, Esc means No).
- `Typewriter`: 40 characters per second; the first Enter reveals the rest, the second finishes.
- Status panel: rows 0-4. Row 1: name, path, level, HP bar (20 cells, colored by the >50% / >20% thresholds), Fervor bar labeled `FV` (8 cells; the player-facing name of MP). Row 2: ATK/DEF/LIFE including equipment, EXP, Next, Gold. Row 3: `Weapon <name>[+N]   Armor <name>`, with `+N` only above upgrade 1 and `—` for an empty slot. Text is clipped at the border, never drawn over it.

**Screens so far:**
- **Title:** banner, New Game / Continue / Quit. Continue is disabled when no save file exists. If the save was made with mods that aren't loaded now, Continue first asks "This save used mods that are missing: <list>. Continue anyway?" (see `mods.md`). Continue loads the save; on any load error a MessageBox explains it (damaged, newer version, unreadable), the file is left untouched and the Title stays, so New Game is still available. A successful load marks the save as owned and goes to the Hub with "Welcome back, NAME."
- **Intro:** the opening story on a typewriter (Enter reveals, Enter again continues). Esc returns to the Title.
- **Create Hero:** name (TextInput, max 8; invalid names show `describe(InvalidName)` and ask again), then the path-intro story, then the WARRIOR PATHS menu with a preview box (cols 30-78: name, flavor, base stats as HP / Fervor / ATK / DEF / LIFE, EXP multiplier, the path's sprite). Enter creates the game with `--seed` or, without it, one `std::random_device` value, marks it unsaved and goes to the Hub. Esc on the name returns to the Title; Esc later returns to the name.
- **Hub:** status panel, hero sprite at (4, 6), menu at (34, 7): Explore, Training, Mission, Town, Save, Quit (number shortcuts 1-6). Explore opens the Overworld (see `overworld.md`). It is disabled like Training, and also when the last Hub frame was the phone layout. Training and Mission are disabled with a dim reason when the hero can't adventure ("Fallen: visit the Prior" at 0 HP, else "Equip a weapon and armor"); Mission is also disabled below the lowest mission level ("Requires Lv 15", from Avaritia). The menu refreshes every step, keeping the selection. Row 22 shows the last message; the "Next:" line (`nextGoal`) sits above it (row 21 compact, row 37 large, row 20 phone). It is recomputed only when the state differs from the one it was last computed for, never per frame.
  - **Save:** if a save file exists that this session neither loaded nor wrote, it first asks "Replace the existing save?" (No keeps the file). A successful save clears `dirty`, marks the file owned and shows "Game saved."; a failure shows why and leaves the old save as it was.
  - **Quit / Esc:** quits at once if nothing is unsaved, otherwise asks "Quit without saving?".
  - Training opens Training Setup, Mission opens Mission Select, Town opens the Town menu.
- **Training Setup** (title THE CATACOMBS): status panel, "Your odds of winning a round", and all 30 caves in three columns ("Cave 12  ≈85%", green from 80%, gold from 50%, red below), computed once on entry. Below: "Cave level (1–30)" with a live line "Wins pay 300–570 gold and 300 EXP; a streak fills the pot.". Enter starts a `TrainingSession` (marking the game unsaved) and the playback replaces the screen. A refused session shows `describe()` and returns to the Hub. Esc returns to the Hub without training.
- **Training Playback** (title "THE CATACOMBS · Level N"): hero sprite left, `monster.sprite` at (56, 6) with its name and HP bar below, the hero's HP bar at the bottom. The round's events replay at 10 per second (HP bars follow each `Damaged`/`Healed`), "Streak S · Pot P gold" (gold) on the title row. Each round is fought and applied when it starts; its events replay at 10 per second (HP bars follow each `Damaged`/`Healed`), and Enter or Esc finishes the round. Then the summary ("Round 3 · Bat defeated · +1000 gold · +1000 exp · Drop: Rosary", or "· Bag full, Rosary lost", "Stalemate with the Bat · the streak is broken") sits above a Continue / Leave choice with "Next round ≈P% · Leave banks the pot" in the odds color (P for the hero's current HP). Nothing happens until the player chooses; Esc means Leave. A defeat shows "Defeated by the Bat · the N gold pot is lost" (when there was one) with "Enter see the results", and goes to the totals by itself after 1 s.
- **Training totals** (title CATACOMB RESULTS): status panel (already showing the new values), rounds won of rounds fought, gold and EXP as the net change since before the session (EXP can be negative after a defeat), levels gained (with "· N blessings at the Prior" when any), drops (and drops lost to a full bag), "Pot banked    +P gold (included above)" after leaving with a pot, and "ARIA has been injured badly" plus "The N gold pot is lost" in the damage color after a defeat. Enter returns to the Hub with "Training: won W of N rounds, banked a P gold pot." or "Training: won W of N rounds, then fell.".
- **Town screens** (`src/app/screens/town.hpp`): the Town menu, titled CIVITAS LUCIS (Almonry, Forge, Prior, Thesaurus, Back) and each NPC screen show the status panel, a title on row 5, their content on rows 6-21 and a dim hint on row 22. Esc goes back one screen. Every action goes through the `game::` town function; a refusal shows its `describe()` text and changes nothing, a success marks the game unsaved. Dialogs (message, yes/no, number or name prompt, a choice list with Esc to back out) open one at a time over the screen, and the next step of a flow opens when the previous dialog closes.
  - **Almonry** (the merchant, title ALMONRY): a fallen hero only sees "The Almonry serves the living. See the Prior first." and is sent back. Otherwise "For sale" (items with a price, price in gold color) on the left and "Your bag" (10 slots, "(empty)" dim) on the right; Tab switches lists, and the highlighted item's description shows on row 19. Enter on a for-sale item asks "How many? (1–99)" with a live total, then buys. Enter on a bag item offers Sell (asks how many, up to what you hold), Auction and Cancel, with the ones that don't apply disabled and a note saying why. An auction is settled immediately (the item and gold change at once); if it sold, the accepted bids appear one every 600 ms ("Bid accepted at 550…", opening bid first) and then "Merchant fee is 10%. You receive N gold."; Enter skips the show. If nobody came: "No buyer came. The Rosary stays in your bag."
  - **Forge** (the blacksmith, title FORGE OF THE ORDER): a fallen hero sees "No blade for an empty soul. See the Prior first." and is sent back. Change Equipment: pick a slot, then a weapon or armor from the bag; swapping out gear above Lv 1 first asks "Your upgraded weapon will return to Lv 1. Continue?". Upgrade: pick an equipped slot, then the screen shows "Sword  Lv 1 → Lv 2" and the material, EXP and gold costs, each line green if you have enough and red if not; Enter asks to confirm (at Lv 10 it says the item is maxed). Forge: the recipes, with the highlighted one's ingredients as have/need counts (green or red) and the success chance; Enter confirms, then "Forging SUCCESS!!! You now possess X" or "Forging FAILED, the materials are lost...".
  - **Prior** (the guildmaster, title THE PRIOR): a hero at 0 HP is revived on entry with "Rise. Mercy asks only that you be more careful. (N gold to the poor box)". Restoration lists the bag's consumables and uses one. Blessings ("Blessings (N)"; disabled with "Level up to earn more" at 0 points) offers "Spend a blessing (N left)" with each stat and its gain ("Max HP +30", "Max Fervor +10", "ATK +6", "DEF +3"), spends one point at once, and says "Your ATK rises to N. 1 blessing left.". Build Charisma (disabled below Lv 10 with "Requires Lv 10") picks a stat (Max HP, Max Fervor, ATK, DEF), asks "EXP to sacrifice" with a live "→ +G Max HP for P gold" preview (the stat's display name), then confirms. Learn Skill lists the skills with their level, gold and key item, each green when met and red when not ("Learned" once known); Enter learns. Change Name shows "The fee is 50000 gold." and asks for the new name.
  - **Thesaurus** (the bank, title THESAURUS): without an account it asks "Open a place in the Thesaurus for 10000 gold?" (No, or a refusal, goes back). With one: "Bank" | "Your bag", Tab switches, Enter asks how many and moves them (works for a fallen hero too).
- **Mission Select:** status panel and every mission from data in file order (Act I: "Avaritia", "Gula" and "Ira", then Bonus: "The Gorgon"), then two disabled "Coming Soon" rows. A mission is disabled with `missionBlocker` (`widgets.*`, shared with the Overworld's lairs): "Cleared" (completed and not repeatable), "Requires Lv N", or the Hub's adventure reason. Enter opens its intro; Esc returns to the Hub.
- **Mission Intro:** the mission name and location, the story on a typewriter, then the ConfirmBox "Enter the lair?". Yes calls `startMission` (marking the game unsaved, since the battle's random stream is forked from the save's) and opens the battle; No or Esc goes back to Mission Select, or pops back to the Overworld when a lair opened it (`fromWorld`). A refused start shows why and pops.
- **Battle:** row 0 has the location and "Turn N" (the turn being played, or the one about to start). `BattleView` (`src/app/battle_view.hpp`) draws the arena (hero at (6, 4), enemy at (44, 2)), HP and status rows 16-17 and the newest 4 log lines on rows 18-21. Row 22 is the Attack / Skill / Item / Defend / Flee row (←/→, `1`-`5`). Item opens the same kind of overlay listing the battle's consumable stock as "Holy Water x2" with descriptions (with nothing to use, the log says "You carry no items to use."); Defend acts at once. Skill opens a boxed overlay ending on row 20 (rows 14-20 with the five base skills; it grows upward when mods add skills) listing every skill as `Name (Fervor cost)`, with " Skills · Fervor cost in () " on its top border, with its description, dim when unlearned or unaffordable (Esc closes it). A rejected action is logged and the turn stays. New log lines: "ARIA uses Holy Water.", "ARIA regains 10 Fervor.", "ARIA raises a guard." / "lowers the guard.", "MEDUSA is gathering its strength!". New tags: `[GUARD n]`, `[CHARGE]`. A failed skill script logs "Something went wrong with that skill's magic.". A script's `ctx.say` line shows in the log for 0.5 s, and an enemy script error as "Something went wrong with <ENEMY>'s magic.". Each action's events queue in the view and play one at a time with ui.md's durations, log lines, flashes, rising "-N"/"+N"/"BLOCK" numbers (1 s), banners on row 9 and the skill-cast shake. Bars and tags change as each event starts, and are set from the battle's real values once the queue is empty. While events play only Enter counts: it finishes the current animation. The mission result is applied with `finishMission` the moment the battle ends; the Result screen replaces the battle once the last event has played.
- **Result:** status panel (already updated). Victory: "VICTORY", EXP, gold, levels gained ("Level up! +2 · 2 blessings at the Prior"), items, and items lost to a full bag in the damage color. Defeat: "DEFEAT" and "All equipment destroyed!" in the damage color. Fled: "You escaped.". Draw: "The battle was a stalemate.". Enter returns to the Hub with a matching last message.
- **Large layouts** (`src/app/art.hpp`): four screens draw a 120x40 layout when `--layout auto`, the terminal is at least 120x40, and every sprite they show has large art in the `--art` look (`glyph` by default, `blocks` for half-blocks). Otherwise they, and every other screen, use the 80x24 layout centered as before. The choice is made each frame from the top screen's `canvasSize`, so a live resize switches layouts. Each screen picks its layout from the size of the frame it is given, and screen state never depends on it, so a mid-battle resize keeps the battle exactly as it was. Shared widgets (centered text, dialogs, the status panel) measure the frame, so they are unchanged at 80x24 and full width at 120x40.
  - **Battle:** `BattleView` draws from a `BattleLayout`. The compact one is ui.md's (a test pins its frames byte-for-byte to the pre-change output). The large one has the 48x24 hero at (6, 3) and the 56x26 enemy at (60, 2), the banner on row 14, stats on rows 29-30 (the enemy's from col 62), and six log lines on rows 32-37. Actions are on row 38, the hint on row 39, and the skill overlay at rows 26-32 from col 28.
  - **Hub:** the status panel is 120 wide, the hero at (4, 7), the menu at (60, 12), and the last message on row 38.
  - **Create Hero:** only the path step is large: a 79x32 preview box from col 40 with the sprite at (66, 8). The name and story steps stay 80x24.
  - **Training playback:** the hero at (6, 4), the 32x16 monster at (80, 8) with its stats on rows 25-27, the hero's name and bar on rows 29-30, and the summary on row 38. Setup and totals stay 80x24.

**Spec drift:** ui.md puts the Create Hero sprite at col 60, where a 24-wide sprite would run past column 79, so it is drawn at col 52 inside the preview box. `App` takes the terminal (as `LoopIo`), the renderer and the first screen instead of the `Session` from interfaces.md §14, since it never uses the session itself. `Session` also carries the loaded sprites, the `--seed` for new games and `saveOwned` (for the save-overwrite confirm), which interfaces.md §14 doesn't list. `Screen::canvasSize` takes only the terminal size (add-large-art-layout's design passes the options too). Screens read `--layout` and `--art` from the session. The Blacksmith's Upgrade view writes levels as "Lv 1 → Lv 2" rather than the status panel's "+N" so level 1 has a name. ui.md's battle row 16 puts both HP bars and numbers on one line, which needs 83 columns, so the enemy's HP numbers (and its status tags) are on row 17 under its name.

## Phone layout (portrait, 48×44)

Every screen has one. It is used when `--layout portrait` is given or, in `auto`, the terminal is narrower than 80 columns (`portraitOr`); `--layout compact` never uses it. Everything can be done by tapping, with the phone's keyboard closed.

- **Bands:** header rows 0–5 (`drawHeader`: title, up to four dim labels over values, a rule), scene rows 6–21, menu band rows 22–31 (`drawButtonMenu`: the screen's `Menu` in a box, up to 8 rows, tappable), control pad rows 32–43.
- **✕ and pad:** the App draws them over every portrait frame (`drawControls`): ✕ at the top right, and 14×3 boxes ✕ Back and ▲, ◀ ● ▶, ▼. Taps on them reach the screen as Esc, the arrows and Enter (`controlKey`), so screens have no pad code.
- **Hub:** header "ARIA · Knight" with LEVEL, HP (HP color), FERVOR and GOLD, a full-width HP bar, the hero's compact sprite centered, the last message on row 21, and the menu in the band.
- **Dialogs** wrap to the frame they're drawn on (at most 60 columns, 4 less than the frame), so they fit the phone layout too.
- **Typing without a keyboard:** number inputs (cave level, amounts, Charisma EXP) show a digit keypad (1–9, ⌫, 0, OK) in the menu band, and ▲▼ change the number by 1, ◀▶ by 10. Name inputs (new hero, Change Name) show a letter keypad (A–Z, 0–9, ␣, ⌫, OK). `keypadKey` turns a tap on a key into that key; the screens that own an input remember whether they were last drawn on the phone layout, so taps only count as keypad keys there.
- **Menus** longer than 8 rows scroll in the band with ▲/▼ marks on its border. Side-by-side menus (the battle actions, Continue/Leave) are stacked as rows and also take ↑↓.
- **Screens:** Title (banner, menu in the band); Intro, Create Hero story and Mission Intro (text wrapped to 44, "● continue"); Create Hero name (letter keypad) and paths (sprite left, stats right, paths in the band); Hub (above); Mission Select (the highlighted mission's location and level); Battle (location and turn on row 0, the enemy's stats on rows 1–2 and the hero's on 3–4, only the enemy's sprite, 3 log lines on rows 19–21, actions or the Skill/Item overlay in the band, "● skips the animation" while events play); Result and Catacomb results (lines from column 1); Training (30 caves in two columns with odds, then the digit keypad); Training rounds (STREAK / POT / NEXT header, both sprites and bars, the summary and Continue/Leave in the band); town screens (hero header; Almonry and Thesaurus show one list at a time, ◀▶ or Tab switch, with the highlighted item's description above; Forge's recipes in the band with ingredients above; Prior's skills in the band with the highlighted skill's needs in green/red above). Pop-ups that choose, ask a number or a name use the scene and the band; messages and yes/no questions stay centered dialogs.
