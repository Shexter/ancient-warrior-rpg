# App: screens and widgets

**Command line:** `heroes [--seed N] [--data-dir PATH]`. Unknown options or bad values print the error and usage to stderr and exit 2. The data directory is `--data-dir`, else `HEROES_DATA_DIR`, else the source tree's `data/`. Content errors are printed one per line and the game exits 2 **before** the terminal is switched to raw mode or the alternate screen (a CTest case checks this). Sprites are loaded next (`<data-dir>/../assets/sprites`: `hero_<path>.sprite` for every path, every enemy's sprite, `monster.sprite`); a missing or invalid one is printed and the game exits 2, also before the terminal changes. If no save location can be found (no `HOME`/`APPDATA` and no `HEROES_SAVE_DIR`) it exits 2. Other startup failures (for example not running in a terminal) print `heroes: error: ...` and exit 1 after the terminal is restored.

**Session:** content, the loaded sprites, the save path, the `--seed` for new games, the current `GameState` (none until a game is started or loaded), `dirty` (changed since the last successful save), `saveOwned` (this session loaded or wrote the save file) and the Hub's last message.

**App:** a stack of `Screen`s on the fixed-step loop. Each step the top screen gets the new keys and returns `Stay`, `Push`, `Pop`, `Replace` (pop then push) or `Quit`. Quit, or popping the last screen, ends the program with exit code 0. Only the top screen is drawn; dialogs are drawn by the screen that owns them. The canvas is 80x24, centered in larger terminals with the `bg` color around it.

**Widgets** (`src/app/widgets.hpp`, colors from ui.md's palette):
- `Menu`: vertical (↑/↓, `w`/`s`) or horizontal (←/→, `a`/`d`). Selection wraps and skips disabled items; Enter or `1`-`9` chooses an enabled item. The selected row shows `▶` in the accent color, disabled rows are dim, and an optional dim note follows the label. An unfocused menu (the other list of a two-list screen) hides its `▶`.
- `TextInput` (printable ASCII up to a max length, blinking `_`), `NumberInput` (digits only, no more digits than the maximum has; Enter on an empty or out-of-range value shows "Enter a number from MIN to MAX" in the damage color).
- `MessageBox` (centered, at most 60 columns, word-wrapped, Enter or Esc dismisses), `ConfirmBox` (`Y`/`N`, Esc means No).
- `Typewriter`: 40 characters per second; the first Enter reveals the rest, the second finishes.
- Status panel: rows 0-4. Row 1: name, path, level, HP bar (20 cells, colored by the >50% / >20% thresholds), Fervor bar labeled `FV` (8 cells; the player-facing name of MP). Row 2: ATK/DEF/LIFE including equipment, EXP, Next, Gold. Row 3: `Weapon <name>[+N]   Armor <name>`, with `+N` only above upgrade 1 and `—` for an empty slot. Text is clipped at the border, never drawn over it.

**Screens so far:**
- **Title:** banner, New Game / Continue / Quit. Continue is disabled when no save file exists. Continue loads the save; on any load error a MessageBox explains it (damaged, newer version, unreadable), the file is left untouched and the Title stays, so New Game is still available. A successful load marks the save as owned and goes to the Hub with "Welcome back, NAME."
- **Intro:** the opening story on a typewriter (Enter reveals, Enter again continues). Esc returns to the Title.
- **Create Hero:** name (TextInput, max 8; invalid names show `describe(InvalidName)` and ask again), then the path-intro story, then the WARRIOR PATHS menu with a preview box (cols 30-78: name, flavor, base stats as HP / Fervor / ATK / DEF / LIFE, EXP multiplier, the path's sprite). Enter creates the game with `--seed` or, without it, one `std::random_device` value, marks it unsaved and goes to the Hub. Esc on the name returns to the Title; Esc later returns to the name.
- **Hub:** status panel, hero sprite at (4, 6), menu at (34, 7): Training, Mission, Town, Save, Quit. Training and Mission are disabled with a dim reason when the hero can't adventure ("Fallen: visit the Prior" at 0 HP, else "Equip a weapon and armor"); Mission is also disabled below the lowest mission level ("Requires Lv 20"). The menu refreshes every step, keeping the selection. Row 22 shows the last message.
  - **Save:** if a save file exists that this session neither loaded nor wrote, it first asks "Replace the existing save?" (No keeps the file). A successful save clears `dirty`, marks the file owned and shows "Game saved."; a failure shows why and leaves the old save as it was.
  - **Quit / Esc:** quits at once if nothing is unsaved, otherwise asks "Quit without saving?".
  - Training opens Training Setup, Mission opens Mission Select, Town opens the Town menu.
- **Training Setup** (title THE CATACOMBS): status panel, then "Cave level (1–30)" and "Rounds (1–100)" NumberInputs. On the second Enter the whole session runs at once through `runTraining` (gold, EXP, drops and HP are applied immediately and the game is marked unsaved), then playback replaces the screen. A refused session shows `describe()` and returns to the Hub. Esc returns to the Hub without training.
- **Training Playback** (title "THE CATACOMBS · Level N"): hero sprite left, `monster.sprite` at (56, 6) with its name and HP bar below, the hero's HP bar at the bottom. The round's events replay at 10 per second (HP bars follow each `Damaged`/`Healed`), then the round summary ("Round 3/10 · Bat defeated · +1000 gold · +1000 exp · Drop: Rosary", or "· Bag full, Rosary lost", "Defeated by the Bat", "Stalemate with the Bat") stays up for 1 s before the next round. Enter finishes the current round (or ends the pause); Esc jumps to the totals.
- **Training totals** (title CATACOMB RESULTS): status panel (already showing the new values), rounds won of rounds fought, gold and EXP as the net change since before the session (EXP can be negative after a defeat), levels gained, drops (and drops lost to a full bag), and "ARIA has been injured badly" in the damage color after a defeat. Enter returns to the Hub with "Training: won W of N rounds.".
- **Town screens** (`src/app/screens/town.hpp`): the Town menu, titled CIVITAS LUCIS (Almonry, Forge, Prior, Thesaurus, Back) and each NPC screen show the status panel, a title on row 5, their content on rows 6-21 and a dim hint on row 22. Esc goes back one screen. Every action goes through the `game::` town function; a refusal shows its `describe()` text and changes nothing, a success marks the game unsaved. Dialogs (message, yes/no, number or name prompt, a choice list with Esc to back out) open one at a time over the screen, and the next step of a flow opens when the previous dialog closes.
  - **Almonry** (the merchant, title ALMONRY): a fallen hero only sees "The Almonry serves the living. See the Prior first." and is sent back. Otherwise "For sale" (items with a price, price in gold color) on the left and "Your bag" (10 slots, "(empty)" dim) on the right; Tab switches lists, and the highlighted item's description shows on row 19. Enter on a for-sale item asks "How many? (1–99)" with a live total, then buys. Enter on a bag item offers Sell (asks how many, up to what you hold), Auction and Cancel, with the ones that don't apply disabled and a note saying why. An auction is settled immediately (the item and gold change at once); if it sold, the accepted bids appear one every 600 ms ("Bid accepted at 550…", opening bid first) and then "Merchant fee is 10%. You receive N gold."; Enter skips the show. If nobody came: "No buyer came. The Rosary stays in your bag."
  - **Forge** (the blacksmith, title FORGE OF THE ORDER): a fallen hero sees "No blade for an empty soul. See the Prior first." and is sent back. Change Equipment: pick a slot, then a weapon or armor from the bag; swapping out gear above Lv 1 first asks "Your upgraded weapon will return to Lv 1. Continue?". Upgrade: pick an equipped slot, then the screen shows "Sword  Lv 1 → Lv 2" and the material, EXP and gold costs, each line green if you have enough and red if not; Enter asks to confirm (at Lv 10 it says the item is maxed). Forge: the recipes, with the highlighted one's ingredients as have/need counts (green or red) and the success chance; Enter confirms, then "Forging SUCCESS!!! You now possess X" or "Forging FAILED, the materials are lost...".
  - **Prior** (the guildmaster, title THE PRIOR): a hero at 0 HP is revived on entry with "Rise. Mercy asks only that you be more careful. (N gold to the poor box)". Restoration lists the bag's consumables and uses one. Build Charisma (disabled below Lv 10 with "Requires Lv 10") picks a stat (Max HP, Max Fervor, ATK, DEF), asks "EXP to sacrifice" with a live "→ +G Max HP for P gold" preview (the stat's display name), then confirms. Learn Skill lists the skills with their level, gold and key item, each green when met and red when not ("Learned" once known); Enter learns. Change Name shows "The fee is 50000 gold." and asks for the new name.
  - **Thesaurus** (the bank, title THESAURUS): without an account it asks "Open a place in the Thesaurus for 10000 gold?" (No, or a refusal, goes back). With one: "Bank" | "Your bag", Tab switches, Enter asks how many and moves them (works for a fallen hero too).
- **Mission Select:** status panel and every mission from data, then two disabled "Coming Soon" rows. A mission is disabled with "Cleared" (completed and not repeatable), "Requires Lv N", or the Hub's adventure reason. Enter opens its intro; Esc returns to the Hub.
- **Mission Intro:** the mission name and location, the story on a typewriter, then the ConfirmBox "Enter the lair?". Yes calls `startMission` (marking the game unsaved, since the battle's random stream is forked from the save's) and opens the battle; No or Esc goes back to Mission Select. A refused start shows why and returns to the Hub.
- **Battle:** row 0 has the location and "Turn N" (the turn being played, or the one about to start). `BattleView` (`src/app/battle_view.hpp`) draws the arena (hero at (6, 4), enemy at (44, 2)), HP and status rows 16-17 and the newest 4 log lines on rows 18-21. Row 22 is the Attack / Skill / Flee row (←/→, `1`-`3`); Skill opens a boxed overlay at rows 14-20 listing every skill as `Name (Fervor cost)`, with " Skills · Fervor cost in () " on its top border, with its description, dim when unlearned or unaffordable (Esc closes it). A rejected action is logged and the turn stays. Each action's events queue in the view and play one at a time with ui.md's durations, log lines, flashes, rising "-N"/"+N"/"BLOCK" numbers (1 s), banners on row 9 and the skill-cast shake. Bars and tags change as each event starts, and are set from the battle's real values once the queue is empty. While events play only Enter counts: it finishes the current animation. The mission result is applied with `finishMission` the moment the battle ends; the Result screen replaces the battle once the last event has played.
- **Result:** status panel (already updated). Victory: "VICTORY", EXP, gold, levels gained, items, and items lost to a full bag in the damage color. Defeat: "DEFEAT" and "All equipment destroyed!" in the damage color. Fled: "You escaped.". Draw: "The battle was a stalemate.". Enter returns to the Hub with a matching last message.

**Spec drift:** ui.md puts the Create Hero sprite at col 60, where a 24-wide sprite would run past column 79, so it is drawn at col 52 inside the preview box. `App` takes the terminal (as `LoopIo`), the renderer and the first screen instead of the `Session` from interfaces.md §14, since it never uses the session itself. `Session` also carries the loaded sprites, the `--seed` for new games and `saveOwned` (for the save-overwrite confirm), which interfaces.md §14 doesn't list. The Blacksmith's Upgrade view writes levels as "Lv 1 → Lv 2" rather than the status panel's "+N" so level 1 has a name. ui.md's battle row 16 puts both HP bars and numbers on one line, which needs 83 columns, so the enemy's HP numbers (and its status tags) are on row 17 under its name.
