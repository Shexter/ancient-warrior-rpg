# Save system (`src/game/save.*`, `src/platform/paths.*`)

- `saveGame(state, file, mods)` serializes to JSON (`version: 4`, with `"mods": [{"name", "version"}]` for the active mods and the hero's unspent `blessings`; 64-bit values such as the seed and RNG state are `0x` + 16 hex digits), writes `<file>.tmp`, flushes, then renames over the target. It creates the parent directory. Any failure returns `WriteFailed` and leaves the previous save alone. There is no `fsync`, so a power cut (not a process crash) could still lose the newest save.
- `loadGame(file, content)` never modifies or deletes the file. Results: missing file `NotFound`; unreadable `Unreadable`; version above 4 `NewerVersion` (checked before the rest of the file is looked at); version 1 (before mods) loads with no mods; versions 1 and 2 (before blessings) load with `level − 1` blessing points; versions 1–3 (before expeditions) load with no expedition; everything else wrong, including a malformed `mods` list, `Corrupt`.
- **Expedition** (version 4): `"expedition"` is `null` or a dungeon run in progress: `seed`, `floor`, `hero` `[x, y]`, `rng` `{state, inc}`, `explored` (one bit per tile, row-major, least significant bit first, as hex), `enemies` (`id`, `pos`, `awake`, `sleepTurns`, `elite`) and `chestsOpened` (by the floor's chest order). The loader checks its shape and that enemy ids exist, and fills `GameState::expedition`. Whether it fits the dungeon is checked by `dungeon::fromSave`, which rebuilds the floor (see `dungeon.md`).
- `readSaveMods(file)` returns just the recorded mods (none for version 1), so the Title can warn about missing mods before loading. It never modifies the file either.
- "Wrong" means: invalid JSON, files over 1 MiB, missing or mistyped fields, non-integers, out-of-range numbers (HP above max, level below 1, level or any stat above 1,000,000, gold/exp/expToNext above 10^15, forge level outside 1-10, upgrade level outside 1-10), unknown path/item/skill/mission ids, a weapon slot holding a non-weapon (and likewise armor), a bag or bank that is not exactly 10 slots or stacks the same item twice, an invalid hero name, malformed hex, or an even RNG increment. Extra unknown keys are ignored.
- Bag/bank slot positions (including gaps) round-trip exactly via `Inventory::fromSlots`.
- `platform::saveFilePath()`: `$HEROES_SAVE_DIR/save.json` if set and non-empty; otherwise macOS `~/Library/Application Support/heroes-rpg/save.json`, Linux `$XDG_DATA_HOME` or `~/.local/share` + `heroes-rpg/save.json`, Windows `%APPDATA%\heroes-rpg\save.json`. Returns nullopt when the needed variables are missing. It creates nothing.
